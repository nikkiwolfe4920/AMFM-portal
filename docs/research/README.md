# Research Notes

This directory holds durable research that supports implementation rules, design-system governance, accessibility decisions, token strategy, Figma-to-code workflow, and tool choices.

Research here is supporting evidence, not an implementation rule by itself. A requirement becomes mandatory only when it is promoted into `IMPLEMENTATION.md` with a complete module contract.

## Research Packet Contract

Each research packet should include:

- **Topic**: the implementation or design-system question being answered.
- **Why it matters**: what decision, module, component, or checker behavior it supports.
- **Sources**: canonical links, local files, Figma nodes, specs, or tool docs used.
- **Version/date**: publication/version date when available, plus the date the packet was written or updated.
- **Project interpretation**: how the source material maps to AMFM Portal's tokens, components, docs, tests, or visual audit flow.
- **Decision**: what the repo should do now.
- **Limits**: what this packet does not prove or automate.
- **Verification path**: command, checklist, visual review, or manual confirmation that can prove the decision is being followed.

Do not copy entire external standards or vendor docs into this repo unless the license, update burden, and maintenance process are explicit. Prefer concise project-specific notes backed by canonical references.
